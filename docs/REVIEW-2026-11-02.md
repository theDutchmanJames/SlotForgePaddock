# Review: research, comparisons, lane records and Dealership approval

Reviewed the uncommitted changes following v1.0.1, covering Real Car History,
external research files, the generic webpage reader, manual test conditions,
pace comparisons, lane records and their persistence/sharing paths.

## Findings fixed

1. **Ambiguous Dealership decision dialog.** The old dialog defaulted to rejecting
   a proposal while its primary button said “Confirm decision.” The two reported
   livery proposals were recorded as rejected. Approval itself worked in an
   isolated reproduction. The dialog now has an explicit **Approve changes**
   primary button and a separate **Reject proposal** action, with clear outcome
   messages. Approval was verified for classification and ordinary car edits.
2. **Reference photograph retries.** A failed save could mutate the pending photo
   array and duplicate the image on retry. Each attempt now constructs a fresh
   candidate array. Empty image data is rejected without changing the car.
3. **Research edits and stale context.** Text-only research edits no longer resend
   unchanged photographs. Editors check the database, car and revision context
   before saving, including after file selection.
4. **Evidence after source removal.** Removing a source also removes its URL from
   field evidence. Editing a researched value clears evidence for that value;
   unchanged values retain their uncertainty notes.
5. **Incomplete import preview.** Incoming-car research previews now include
   evidence methods, source URLs and uncertainty notes.
6. **JSON input boundaries.** File reads enforce their size limit while reading,
   including files that grow after opening. Research imports use a 1 MB limit.
   UTF-8 byte-order marks are accepted; malformed encoding and JSON produce
   useful errors.
7. **Web reader resource limits.** HTML node/depth limits are enforced during
   parsing, before a complete oversized DOM can be allocated. Request errors and
   timeouts clean up consistently. Definition-list parsing tolerates comments.
8. **Lane-record calculations.** Record summaries avoid unnecessary median and
   sustained-run calculations and skip unrelated cars' sessions before scanning
   laps. Non-finite manual lap times are excluded, and driver names are trimmed.

  failures and lane-record edge cases.
- Isolated Electron checks passed for explicit approval/rejection, persisted car

  retry, photo preservation, manual test conditions and pace comparisons.

- Windows unpacked application packaging completed successfully.

The user's database was inspected read-only to diagnose the two rejected
proposals. It was not altered. Those changes must be submitted again; restarting
the updated development app loads the clearer approval controls.

Network tests use local server/client instances, not two physical computers.
Webpage extraction checks use fixtures rather than claiming compatibility with
every live website. Native macOS and Linux builds were not run in this review.
No release was published as part of this work.
