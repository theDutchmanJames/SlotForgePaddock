# Illustrated Catalogue — picture requests

Illustrated Catalogue exports picture requests for products already in your library, validates the completed files, and downloads local comparison previews. Selected originals can then be applied locally or submitted to Dealership Review. Standard Catalogue imports keep their existing format and behavior.

1. Open **Import & Export → Illustrated Catalogue → Create picture request**, or use the shortcut in **Library → Parts catalogue**.
2. Choose a manufacturer and apply the filters. Parts and workshop supplies are included by default, whether owned or zero-stock. By default only entries without a picture appear.
3. Select entries individually or use **Select all filtered**. Selections are retained across pages and category/search filters; changing manufacturer or the missing-picture option clears them. Entries without references are marked because finding an exact match may be harder.
4. Export to a folder. Paddock creates a new subfolder containing English instructions and one JSON request per 100 entries, up to 100 files. Give each JSON file to your own AI. There is no built-in AI. Exporting makes no network request.

To request alternatives for existing pictures, turn off **Only entries without pictures** and apply filters. This does not replace those pictures. Use **Select all ready pictures** to include replacements, or select them individually. The missing-picture bulk action never adds replacements for you.

The files contain public product descriptions, references, suitable existing product-page links and opaque row/request identities. They exclude stock quantities, prices, locations, private notes and image bodies. Identical references remain separate entries. A product page is included only when the saved catalogue identity still matches the current record.

**Saved picture requests** lets you export the same request again after a restart or failed export. Discarding a request also removes its staged previews and makes its returned file unusable; it does not delete a product. Requests from another collection or a previous recovery generation are marked and cannot be re-exported here. Unused requests and previews can still be discarded. Requests with an uncertain save or pending Dealership review are retained until their outcome can be checked against the original collection. Exporting a fresh request requires refreshing the selection if the collection changed.

Private mappings and product/photo baselines are saved atomically in `catalogue-picture-requests.sqlite` under Paddock's profile directory before any public file is written. Closing the picker before export saves nothing. A failed file write retains the request for recovery. A combined import accepts up to 100 selected files and 16 MiB of JSON input in total (each file still has its 2 MiB limit). The profile permits 100 saved requests and 16 MiB of combined descriptor and preview-job metadata, including batch membership and remaining download work; it never evicts pending requests automatically. These local workflow records are not part of a library backup and do not travel to another computer with it.

Browsing and preparing selections use read-only SQLite snapshots on background workers, with 40 visible rows per page. Photo originals are not loaded. Journals do not change the shared collection schema, stock, cars, racing results or Timing/Telemetry APIs. Dealership copies can export from their current snapshot; application rechecks the authority's current records.

## Download and compare pictures

1. Choose **Open completed picture files…** on the Illustrated Catalogue card and select all the returned JSON files you want to process together. Paddock validates every selected file before saving the batch or fetching any image. An invalid file is identified by filename and leaves the whole selection unstarted; correct it or leave it out and select again. Repeated files reuse their existing request and report that reuse. The normal **Import catalogue…** chooser also recognizes a single picture-response JSON.
2. Check the names, references, source domains and uncertainty notes. The request must belong to this library and its current recovery generation. Changed or removed products need a fresh request. Unreturned rows remain available for a later response.
3. Watch the download progress or choose **Stop downloads**. Failed rows can be retried individually or together with **Download filtered previews**. Existing previews are reused; missing links and changed products are skipped. Successful previews remain saved when you close the window. Files share one bounded queue and one review window, with manufacturer/category/search filters and source filenames. Finish or stop active work before opening another batch. Closing the window preserves the queue and selections. Opening any member through Saved picture requests reopens the combined batch and resumes its waiting downloads unless you explicitly stopped them. Failed URLs are never automatically retried; use Retry download or Download filtered previews.
4. Compare the current and proposed picture. **Select all ready pictures** selects every ready preview in the combined batch, across all pages and filters, including replacements and uncertain matches. Failed, unavailable, unchanged and pending/applied pictures are excluded. Untick any pictures you do not want. Alternatively, **Select ready missing pictures** adds only filtered rows without an existing picture, with a reference and no uncertainty note; it preserves existing selections. Selection buttons never import pictures. **Finish import (N)** in the fixed bottom-right footer respects your ticked choices. It opens one confirmation in that same footer with the total and replacement count. Choose **Confirm import** to continue, or **Back to selection** to change your choices.
5. Use **Edit image links** to correct a URL or remove the proposed link. This clears that row’s preview and selection without changing the product. **Remove preview** clears one staged picture; **Clear unselected previews** frees cache space while retaining selected pictures.
6. Return through **Saved picture requests → Open previews**. Selections are remembered on this computer. They do not apply photographs to the catalogue yet.

Downloads accept still PNG, JPEG and WebP files from public HTTP/HTTPS servers on standard ports. Each destination and redirect is checked; private/local addresses, credentials, HTTPS downgrades, compressed HTTP bodies and unsupported content are rejected. URLs are fetched in the main process without browser cookies. No image or product-page link is automatically loaded by the interface.

Original source bytes are preserved in private staging. Full decoding runs in a cancellable worker, then the interface displays only local thumbnails up to 512px, preserving proportions and transparency. Originals must fit the existing 12 MiB data-URI limit (at most 9,437,166 source bytes), 24 megapixels and 16,384 pixels per side. Oversized originals are rejected, not silently reduced.

The service admits at most two downloads and one decode at a time. Network attempts have a 15-second deadline including DNS; each item has a 30-second deadline, and each decode has a 10-second deadline. Quota is reserved before downloading and free disk space is checked. Staging across all jobs is capped at 64 MiB. A queued download waits for capacity reserved by an active download; it does not mark the remaining products as failed. When there is genuinely too little room for another bounded download, the queue pauses and shows how many pictures are waiting. Import ready pictures to free staging: the remaining queue continues automatically after confirmed saves. After clearing unwanted previews or freeing disk space, choose **Resume downloads** to resume the whole saved queue. Free disk space is handled in the same way. Unselected inactive previews without a save attempt expire after 72 hours; selected, currently displayed and retryable save evidence remain protected within the same quota. After a restart, opening the combined batch resumes queued work unless it was explicitly stopped. Failed URLs still require an explicit retry. Incomplete files never become ready previews.

The profile-only cache and journal are not included in a library backup. Restoring/replacing the library invalidates old request baselines; the app never silently rebinds them to the new recovery generation. Product/photo changes invalidate a proposal, while unrelated stock changes do not. A failed picture download never modifies or removes an existing photograph.

The [v1 contract](contracts/catalogue-pictures-v1/CONTRACT.md) specifies the exact resource limits, identities and application/receipt rules. Application writes only the selected pictures and provenance; no Timing/Telemetry capability changes are required.

## Import and recover

1. Use **Select all ready pictures**, or tick the pictures to keep, then choose **Finish import (N)** in the fixed bottom-right footer. Check the count and the number of existing photographs being replaced, then choose **Confirm import**. Product specifications, quantities, reservations, installations and racing history are not edited. The downloaded original is stored without resizing; previews remain small.
2. In a local collection, each picture is saved separately with its source information and durable receipt. In **Dealership Mode**, each selected product becomes a pending picture proposal. The host sees the product name and current/proposed photographs in Review. Only approval applies the picture; rejection preserves the original. An updated host advertising catalogue-picture support is required.
3. **Stop import** stops after the in-flight operation settles. It does not undo saved pictures or cancel pending reviews. Closing the window also leaves saved progress available in **Saved picture requests**.
4. Use **Check import status** after an interruption or host decision. **Retry incomplete imports** reuses the original operation identities and checks receipts first. A lost response cannot cause a second replacement. Pending means awaiting approval, not applied.
5. A changed product, changed photograph, expired field baseline or restored collection requires fresh review/context; Paddock never silently rebases an old request. After a restore, old uncertain work stays retained until checked against its original recovery generation. A failed connection is not evidence that a save failed.

When every selected picture is confirmed imported, unchanged, or submitted for review and no downloads were waiting, the window closes automatically and the catalogue refreshes. If downloads were waiting, the window stays open, shows the completed import and automatically downloads the next pictures as space becomes available. Those new pictures remain unselected: select them and confirm Finish import again when ready. Pending Dealership proposals keep their temporary originals until approval is retrieved with Check import status; only then can that space be reused. A message distinguishes **imported successfully** from **submitted for review**. Unselected pictures are left alone. If any chosen picture fails, has an uncertain outcome, or the import is stopped, the window stays open with progress and recovery controls. Reopening a saved request for inspection does not automatically close it. When pictures are already saved and no ready pictures or queued downloads remain, the footer offers **Done** to close without saving again.

After a confirmed local import, or a confirmed Dealership approval retrieved through **Check import status**, Paddock removes the temporary original and comparison thumbnails. The full-resolution picture in the library and the durable import receipt remain intact. Downloads identical to an existing stored picture also release their redundant temporary copies. Completed staging left by earlier versions is cleaned up automatically; interrupted cleanup retries without treating an already saved picture as a failed import.

Pending or uncertain operations pin their staged originals and cannot be edited or discarded. Finished requests may be discarded without removing their applied photographs. Applied photographs and source information travel in library backups; private workflow journals do not. Manual replacement of a picture clears its previous catalogue-source attribution.

Downloads still use the existing 64 MiB staging allowance. Dealership review budgets both the existing and proposed original against the existing 16 MiB proposal limit; an oversized replacement is refused without changing either picture. No Timing or Telemetry update is required for these picture features.
